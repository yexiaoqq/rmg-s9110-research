# RMG-S9110 研究日志

> 把一个开源内核提权工具适配到一台三星 Galaxy S23 上的**真实研究记录**。
> 本仓库面向完全新手写作：每个名词都会解释，每一步实验都留档在 [journal/](journal/)。

## 0. 三句话看懂

1. 我们想让一台 **三星 Galaxy S23（型号 SM-S9110，代号 dm1q）** 用开源项目 **Root My Galaxy**（利用漏洞 **CVE-2026-43499**）拿到**临时 root** 权限。
2. 硬性前提：**绝不能触发 Knox 熔断**——否则 Samsung Pay、安全文件夹、银行 App 会永久失效。所以放弃 Magisk / 永久 Root 这条路。
3. 目前进度：**KASLR 泄露（拿到内核基址）已经跑通**；卡在最后一步——**“页碰撞 grooming”** 只能找到 0～3 个碰撞，凑不够需要的数量，于是 exploit 中止。

如果只想知道“现在做到哪了”，直接看：[当前进展与卡点](docs/03-当前进展与卡点.md)。

## 1. 一分钟比喻

- **root** = 手机的“超级管理员”。拿到它，才能干系统级的事。
- **Knox** = 三星的安全保险丝。一旦检测到系统被改动，它会**永久熔断**，无法恢复，相关 App 全部罢工。
- **漏洞（CVE-2026-43499）** = 系统内核里的一个程序设计缺陷，可以被“骗”着交出权限。
- **payload** = 真正去执行这个“欺骗”过程的一小段程序（一个 `.so` 文件）。
- **KASLR** = 系统为了防止攻击，每次开机都随机摆放内核代码的位置。**想知道打哪里，得先猜出这堆代码被摆在哪**。
- **grooming（堆整理）** = 在动手前，先想办法把内存“摆成我们想要的样子”。就像偷东西前先把房间里的东西挪一挪，好让目标露出来。
- **碰撞（collision）** = grooming 里的一种“凑齐同类”的动作。本次失败点就是**同类凑不够数**。
- **Shizuku** = 一个免 root 的权限授权工具。它能让 App 借用 `shell` 身份（比普通 App 权限高，但**不碰系统分区**），正好绕开 Knox。

## 4. 为什么要有这个仓库

研究过程最怕两件事：**忘掉自己做过什么**、**拿到结果却不知道当时的环境**。
所以这里立规矩：

> **每一次实验、每一次分析、每一次失败，都写一条 journal，只增不删。**

失败尤其要记——它排除了一个可能性，本身就是成果。规范见 [journal/README.md](journal/README.md)。

---

## 5. 红线（不可违反）

1. **不写 boot / vendor / system 分区**，不碰启动链（保 Knox 的底线）。
2. 不做任何持久化改动（除非用户明确知情并同意）。
3. 每次实跑 exploit 前**必须**获得设备主人明确授权——这类实验有 **panic→重启** 风险。
4. 实跑前后核对安全基线：`ro.boot.flash.locked=1` / `verifiedbootstate=green` / `warranty_bit=0`。

详见 [DISCLAIMER.md](DISCLAIMER.md)。
