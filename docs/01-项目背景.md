# 01 · 项目背景

## 1. Root My Galaxy 是什么

[Root My Galaxy](https://github.com/BuSung-dev/Root-My-Galaxy) 是一个**开源**的三星手机内核提权工具，用公开漏洞 **CVE-2026-43499** 为三星设备获取 **临时 root**。

它的设计非常“数据驱动”：

- App 本体是**型号无关**的，不把任何机型写死在里面。
- 它启动时去 GitHub 的 **payload 仓库**拉一份索引文件（feed，叫 `targets-v3.json`），
  按 **手机型号（Build.MODEL）** 和 **内核版本（uname -r 前三段）** 匹配。
- 匹配上了，就下载对应机型的那份 `.so` payload 并执行。

换句话说：**只要你为某个机型准备好“一份 payload + 一条 feed 记录”，理论上就能支持它。**

## 2. 我们为什么要做这件事

用户的设备是 **三星 Galaxy S23（SM-S9110，代号 dm1q）**：

- 上游的公开支持矩阵里，这台机器对应的内核分支 **android13-5.15 = Untested（未测试）**。
- 也就是说：没人验过，也没人保证能跑通。

同时用户有一条**不可谈判的硬约束**：

> **必须保住 Knox。** 一旦熔断，Samsung Pay / 安全文件夹 / 部分银行 App 永久失效。

于是直接放弃了这些方案：

| 方案 | 为何不用 |
|---|---|
| Magisk / KernelSU（常规） | 需刷 boot 分区 → Knox 熔断 |
| Zygisk / LSPosed | 依附 Magisk；Samsung Pay 读硬件熔断丝，藏不住 |
| DFRoot / DFReroot | 加载未签名内核模块 + 改 vendor/system 分区，属永久内核级 root，失败模式含 bootloop |

**唯一可接受的路线**：临时 root（重启即失效）+ 不碰启动链 + 不写系统分区。

## 3. 我们做了哪些准备工作

1. **自建 payload 仓库**，让 App 能匹配到 SM-S9110：
   - 仓库：[yexiaoqq/Root-My-Galaxy-Payloads01](https://github.com/yexiaoqq/Root-My-Galaxy-Payloads01)
   - flat 布局：两个二进制在根目录 + `support/targets-v3.json`。
2. **重打包 App**：把 App 里 6 处硬编码的 payload 仓库 URL 等长替换成我们自建的仓库，重新签名（`apksigner` v3 校验通过）。
   - 注意：自签签名与原版不同，**无法覆盖安装**，需先卸载原版（会清本地数据）。
3. **向上游提交 PR**：把 SM-S9110 的适配作为 PR #375 提交到上游 payload 仓库。

## 4. 现在的卡点一句话

> KASLR 泄露已经跑通（知道内核摆在哪了），但**最后一步“页碰撞 grooming”只能找到 0～3 个碰撞**，凑不够 payload 要求的数量，exploit 中止。
