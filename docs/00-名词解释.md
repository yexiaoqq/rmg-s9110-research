# 00 · 名词解释（遇到看不懂的词先来这里）

> 本文用**最白话**的方式解释本仓库会出现的所有术语。按需查阅，不必从头读。

## 一、权限与安全类

| 名词 | 白话解释 |
|---|---|
| **root** | Android 里的“超级管理员”。普通 App 只能在自己的小盒子里活动；root 能改整个系统。 |
| **临时 root** | 只在这一段运行期间是 root，**重启后就没了**。不碰系统文件，所以相对安全。 |
| **永久 root** | 把 root 能力写进系统、开机自带。通常要改启动分区，**会熔断 Knox**，本项目放弃。 |
| **提权（privilege escalation）** | 从“普通用户”变成“管理员”的过程。 |
| **Knox** | 三星的安全系统。一旦发现系统被改动，会烧断一根**一次性的“硬件保险丝”**，永久不可逆。后果：Samsung Pay、安全文件夹、部分银行 App 永久失效。 |
| **eFuse / warranty_bit** | 那根“保险丝”。熔断后 `warranty_bit` 从 0 变成 1，无法恢复。 |
| **SELinux** | 系统里的“权限警察”。每个进程有身份标签（域，domain），比如 App 是 `untrusted_app`，shell 是 `shell`，超管是 `su`。不同身份能访问的文件不同。 |
| **untrusted_app / shell / su** | 三种进程身份。App=最低，shell=中等（adb/Shizuku 给的身份），su=最高。 |
| **Shizuku** | 一个免 root 的“授权中介”。它借来 `shell` 身份，让 App 能用 shell 权限执行系统命令，但**不碰系统分区**，所以不熔断 Knox。 |

## 二、漏洞与攻击类

| 名词 | 白话解释 |
|---|---|
| **CVE** | 公开漏洞的编号。本项目用的是 **CVE-2026-43499**。 |
| **payload** | 真正执行攻击逻辑的一小段程序。本项目里是一个 `.so` 文件（共享库）。 |
| **exploit（利用）** | 用漏洞达成提权的整个动作/程序。 |
| **KernelSnitch** | 上游 payload 使用的一种**内核内存泄露**技术（通过 futex 的时序差异去猜内存布局）。 |
| **KASLR** | “内核地址随机化”。系统每次开机都把内核代码**随机换个位置摆**，防止攻击者知道该打哪。想攻击就得先**算出这次摆在哪儿**（泄露 slide 偏移）。 |
| **slide / base** | 就是“这次内核代码摆放的位置偏移”和“起始地址”。算出它们 = KASLR 泄露成功。 |
| **P0 / P1** | 攻击的两个阶段代号。P0 通常指“拿到一个初始的读写原语”，P1 指“扩大战果到完全控制”。 |
| **物理 / 虚拟地址** | 内存有两套门牌号：物理地址=内存条上的真实位置；虚拟地址=程序看到的门牌。 |
| **physmap** | 内核把整块物理内存“平铺映射”到的一段虚拟地址区域。 |

## 三、堆整理（grooming）类

| 名词 | 白话解释 |
|---|---|
| **堆（heap）** | 内核动态分配内存的地方。程序运行时想要内存，就从这里要一块。 |
| **grooming（堆整理）** | 在动手前，先通过一系列 allocations / frees 把内存“整理成我们期望的样子”。**就像偷东西前先把房间里的东西挪一挪，好让目标露出来。** |
| **slab / page** | 内核分配内存的两种粒度。slab 是小块，page 是大块（通常 4KB）。 |
| **controlled mm** | 上游 payload 里“受控的内存管理”阶段——通过大量 mmap 来塑造内存布局。 |
| **collision（碰撞）** | 这里特指：两个**不同**的目标落到了**同一个**哈希桶/槽位里。grooming 的目标之一就是凑够足够多的碰撞。 |
| **futex** | Linux 的一种线程同步机制。payload 用它来“探测”内存状态。 |
| **hash bucket（哈希桶）** | futex 内部把地址按哈希分到若干个“桶”里。桶的数量叫 `hashsize`。 |
| **scans / objects / dma32_skip** | payload 搜索受控内存块时的三个扫描参数，当前是硬编码的 256 / 32 / 8（详见 04 文档）。 |
| **reclaim（回收）** | 系统把不用的内存收回去。payload 会**故意制造内存压力**来触发回收，从而获得可预测的内存布局。 |

## 四、工程类

| 名词 | 白话解释 |
|---|---|
| **APK / dex** | Android 应用包 / 里面的可执行代码文件。 |
| **payload 仓库 / feed** | 上游把各机型 payload 放在 GitHub 仓库里，App 启动时去“下载对应型号的那份”。这个索引文件叫 feed（`targets-v3.json`）。 |
| **tracefs** | 内核的跟踪文件系统，能读到内核内部事件。本项目用它来泄露 KASLR。 |
| **日志（log）** | 程序运行时打印的信息。本仓库的 journal 大量依赖日志来“复现当时发生了什么”。 |
| **哈希（sha256）** | 文件的“指纹”。用来确认两个文件是不是同一个。见 [hashes.md](../hashes.md)。 |
