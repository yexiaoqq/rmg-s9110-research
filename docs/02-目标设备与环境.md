# 02 · 目标设备与实验环境

## 1. 设备

| 项 | 值 |
|---|---|
| 品牌/型号 | 三星 Galaxy S23 / **SM-S9110** |
| 代号（codename） | **dm1q** |
| 芯片平台 | SM8550（骁龙 8 Gen 2） |
| 系统 | Android 16 |
| 固件版本 | **S9110ZCS8FZI1** |
| 内核版本 | **5.15.189-android13-8-3251900-abS9110ZCS8FZI1** |
| 内核 KMI | **android13-5.15** |
| 引导程序 | **锁定**（`ro.boot.flash.locked=1`） |
| 验证启动 | `verifiedbootstate=green` |
| Knox | 未熔断（`warranty_bit=0`） |

> 为什么这些值重要？因为上游 App 就是按 **型号 + 内核版本前三段（5.15.189）** 来匹配 payload 的。任何一项对不上，就会下载到错误的 payload（本项目曾因此踩过坑，见 [journal/](journal/)）。

## 2. 为什么会踩“固件版本”的坑

设备上曾经残留一份 `FZH3` 固件时期的 payload，而本机其实是 `FZI1`。
两个 payload 都叫同一个名字，但**内核常量不同，不能混用**。
所以本仓库专门有 [hashes.md](../hashes.md) 记录**每个关键文件的 sha256 指纹**，用于确认“我现在跑的是不是正确的那一份”。

## 3. 权限与执行环境

| 项 | 说明 |
|---|---|
| Root 方案 | **临时 root**（利用漏洞提权，重启失效，不碰 boot 分区） |
| 权限中介 | **Shizuku**（借 `shell` 身份，免 root，可写 `/data/local/tmp`） |
| 命令执行身份 | `uid=2000(shell) context=u:r:shell:s0` |
| 沙箱 | Ubuntu（proot），**无 git 命令**，所有 GitHub 操作走 REST API |
| adb | 本机**不存在** adb 二进制 |

## 4. 硬约束（不可违反）

1. 不写 **boot / vendor / system** 分区。
2. 不装任何**开机自启**的持久化组件。
3. 不熔断 Knox。
4. 优先**低风险、可逆**的验证方式。
