# 2026-10-02-002 · 碰撞阈值与扫描参数反汇编定位

- **类型**：分析
- **是否实跑**：否（纯静态分析）

## 1. 目标

定位 `only found %zd collisions -> cannot continue` 的碰撞阈值到底在哪，以及它能不能被本地参数影响。

## 2. 假设

如果阈值是硬编码的，或者来自本地可改的环境变量，那我们就能在本地调整它。

## 3. 环境

| 项 | 值 |
|---|---|
| 分析对象 | `/sdcard/Download/u-usr.so`（FZI1 payload） |
| 哈希 | `f8a9560d76bd4d7f86d3f0822960a40fff31a7eb579a0bbe95ef37407ac3909f` |
| 工具 | `objdump -d`、字符串交叉引用 |

## 4. 操作

```bash
# 定位字符串偏移与引用
objdump -d pl.so > pl.dis
python3 - <<'PY'
# 在二进制里搜 "only found %zd collisions" 得到偏移，再用 refs 找引用点
PY

# 反汇编 find_collisions 与 setup
objdump -d --no-show-raw-insn --start-address=0xd014 --stop-address=0xd4e4 pl.so
objdump -d --no-show-raw-insn --start-address=0xccd8 --stop-address=0xcd70 pl.so
```

## 5. 结果

```asm
d288:cmpx21, x23        ; x21=阈值[obj+0x18], x23=实际碰撞数
d28c:b.ned2b0           ; 不相等 → 打印 only found %zd collisions

cd58:strx22, [x19, #24] ; 阈值由 kernelsnitch_setup 第 3 参（x22）写入

; prepare_kernel_page 中打印 controlled mm group search：
; w1=256, w2=32, w3=8  全部立即数硬编码，函数内无 getenv/strtoul
```

## 6. 结论

- 验证了：碰撞阈值来自对象 `+0x18` 字段，由 `kernelsnitch_setup` 第 3 参传入；`scans=256/objects=32/dma32_skip=8` 为硬编码。
- 推翻了：“扫描参数可用环境变量覆盖”的猜测。
- 仍未知：调用 `kernelsnitch_setup` 的上层（如 `prepare_kernel_page` wrapper）到底传了多少作为阈值。

### 附带发现

payload 内置三个诊断开关环境变量：

| 变量 | 作用 |
|---|---|
| `SLIDE_ONLY` | 只跑 KASLR 泄露 |
| `P0_ONLY` | 只跑 P0 |
| `KSNITCH_TIMING_DIAG` | 输出碰撞时序诊断 |
