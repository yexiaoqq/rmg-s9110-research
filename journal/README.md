# journal · 留档规范

> **本仓库的灵魂。**
> 研究过程最怕两件事：忘掉自己做过什么、拿到结果却不知道当时的环境。
> 所以这里立一条铁律：

> ## 每一次实验、每一次分析、每一次失败，都写一条 journal，只增不删。

失败尤其要记——它排除了一个可能性，本身就是成果。

## 1. 文件命名

```
YYYY-MM-DD-NNN-简短标题.md
```

- `YYYY-MM-DD`：日期。
- `NNN`：当日序号，从 `001` 开始，三位数字。
- `简短标题`：中文或英文均可，别超过 20 个字。

例：`2026-10-02-001-碰撞阈值反汇编定位.md`

## 2. 一条 journal 必须包含

1. **目标**：这次想干什么？
2. **假设**：我们期望发生什么？
3. **环境**：设备/固件/权限身份/payload 哈希。
4. **操作**：具体命令、参数。
5. **结果**：看到的输出/日志（关键行原样粘贴）。
6. **结论**：验证了什么 / 推翻了什么。
7. **下一步**：下一个具体动作。
8. **安全核对**：实跑实验必填（`flash.locked` / `verifiedbootstate` / `warranty_bit`）。

可直接复制 [TEMPLATE.md](TEMPLATE.md)。

## 3. 写作原则

- **只增不删**。发现以前写错了，就新开一条写“更正第 N 条”，不回头改旧记录（历史要保真）。
- **不确定就标注“推测”**，并写出依据。不要把猜测写成结论。
- **不夹带隐私**。不要粘贴 IMEI、序列号、手机号、明文 token。
- **能复现**。贴命令，不只贴结论。
- **失败也是成果**。写清楚“为什么失败”比写“成功了”更有价值。
