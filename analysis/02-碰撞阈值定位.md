# 02 · 碰撞阈值定位（“0 collisions” 从哪来）

- **证据文件**：`cve-2026-43499-app.so`、`pl.dis`、`fc.dis`、`prep.dis`
- **工具**：objdump、xrefs 脚本
- **关键地址**：`0xd014`（`kernelsnitch_find_collisions`）、`0xccd8`（`kernelsnitch_setup`）

## 1. 要回答的问题

失败日志反复出现：

```
[*] controlled mm group search scans=256 objects=32 dma32_skip=8
[!] only found 0 collisions -> cannot continue
```

拆成三个子问题：

1. “0 collisions” 是在**哪一行代码**判出来的？
2. 判定的**阈值**从哪来，能不能改？
3. `scans=256 objects=32 dma32_skip=8` 是**硬编码**还是可配置？

## 2. 结论一：判断点位置（事实）

函数 `kernelsnitch_find_collisions`：VA `0xd014`，长度 `0x4d0`。

关键片段：

```asm
d288:  cmp  x21, x23
d28c:  b.ne d2b0        ; 不等则跳到另一分支
...
       ; 命中分支打印：
       ; "only found %zd collisions -> cannot continue"
```

- `x21` 取自 `[x19, #24]`，即对象 `x19` 偏移 `+0x18` 处的字段。
- `x23` 是本次扫描的期望/所需数量。

**事实层面**：判定是“实际碰撞数 vs 期望值”的比较。
**限定语**：寄存器语义由上下文反推，未见源码；若上游公开源码，应以源码为准。

## 3. 结论二：阈值来源（事实）

写这个字段的地方在 `kernelsnitch_setup`（VA `0xccd8`）：

```asm
cd58:  str  x22, [x19, #24]   ; 把 x22 写进对象 +0x18
```

- `x22` 是 `setup` 的**第 3 个参数**（AArch64 调用约定：x0/x1/x2…）。
- 阈值不是 `find_collisions` 内部算的，而是**调用方传进来的**。

**推论**：想在本地改碰撞阈值，必须回到**调用 `kernelsnitch_setup` 的地方**
（如 `prepare_kernel_page` 或更外层 wrapper）改传入值，而不是在 `find_collisions` 里打补丁。

> [推测] 上游针对不同内核版本调整这个值，是“碰撞难度随内核内存布局变化”的适配手段。
> 反例风险：也可能这个参数有其他语义（如扫描次数上限），需运行时验证。

## 4. 结论三：扫描参数是硬编码（事实）

`prepare_kernel_page` 中 `0xee00–0xee08` 连续三条立即数装载：

```asm
ee00:  mov  w1, #256    ; scans
ee04:  mov  w2, #32     ; objects
ee08:  mov  w3, #8      ; dma32_skip
```

这三个数最终用于打印：

```
controlled mm group search scans=%d objects=%zu dma32_skip=%d
```

且该函数体内**没有 getenv / strtoul 调用**（已检索确认）。

**结论**：`scans=256 / objects=32 / dma32_skip=8` 无法通过环境变量调整。
要改只有两条路：① 改二进制并重签；② 找到能间接影响这些值的上游逻辑。

## 5. 副产品：三个可覆盖的诊断开关（事实）

检索环境变量引用时，意外发现 payload 内置三个**诊断用**开关：

| 环境变量 | 字符串地址 | 读取位置 | 作用 |
| --- | --- | --- | --- |
| `SLIDE_ONLY` | `@0x8b74` | `run_exploit` @ `0xc6c8` | 只跑 KASLR 泄露阶段 |
| `P0_ONLY` | `@0xa553` | `run_exploit` @ `0xc6d8` | 只跑 P0 阶段 |
| `KSNITCH_TIMING_DIAG` | `@0x9bd1` | `find_collisions` @ `0xd2c8` | 输出碰撞时序诊断 |

**意义**：这三个开关让我们可以**零风险地分阶段验证**
（只跑 slide / 只跑 P0 / 只输出时序），不必每次都跑完整链。
这是重跑实验前必须利用的信息侧杠杆。

> ⚠️ 注意：即便只跑单阶段，仍会加载内核漏洞代码路径，**并非绝对无风险**。
> 使用前仍需授权，并做好“可能 panic → 重启”的心理与操作准备。

## 6. 本页结论如何被推翻

若后续运行时发现：
- `+0x18` 字段其实不是碰撞数，而是别的计数；
- `scans/objects/dma32_skip` 存在间接覆盖路径（如某个文件配置或 ioctl）；
- 三个诊断 env 不生效或语义不符；

则**新增** `analysis/05-…md` 记录反例，并在本页头部加 `[部分已推翻]` 指向新文，不删旧内容。
